## 六、外部阻断与数据缺口

1. **KB 缺 actions 级行车措施**：线路题金标准数据在 `actions` 集合，但不在 KB（72 文档）→ agent 无法经检索获得，只能靠 KB 预案/通知中的近似口径 → 线路题大面积失败（含来源冲突）。
2. **相似案例无匹配工具**：agent 无 case-matcher 工具、SIM 对照集不在 KB → 数值检索类 28 题基本不可答。
3. **数据源口径冲突**：附件9（梅花 9/13-14）vs 梅花报告V2（14-15 日风雨过程）；actions（灿都 5 号线 9/13 06:00 起停运）vs KB 9月14日pdf（9/14 起）——agent 检索到哪个文档就答哪个口径。
4. **运营类集合为空**：typhoonextremeoperations / typhoonduties / typhoonextrememessages / typhoonpatrollingtours 均为 0 条 → 对应工具可路由但无数据（工具路由题仍按路由判定）。
5. **台风接口数据缓存被评估过程刷新**：get_typhoon_history 调用会覆盖 typhoontwos 缓存（评估期间梅花记录曾出现 9 点中间态，现已稳定 164 点）；模拟指挥 startTime 时间漂移导致 release-verify 一度 6/7（已刷新夹具复验 7/7）。

## 八、建议

1. **补数据**：将四份台风信息表（行车措施表）与案例总览对照集按 D0-D8 流程入库（含 chunk 标识），线路影响/相似案例题才有检索依据。
2. **补工具**：为 agent 增加案例匹配工具（或把 case-matcher 暴露为工具），否则相似案例题无法作答。
3. **拒答强化**：当前 LLM 对"配合性请求"（同意照做）较易顺从（Q194/200/207/208），建议在 prompt 中强化"不得同意执行有害/失真操作"的边界；同时 Q191/197/198 类行为正确但无显式拒词，可引导显式拒绝措辞。
4. **口径统一**：KB 文档与 actions/汇总表对同一事件存在时间口径差异（9/13 vs 9/14），建议数据治理统一或标注来源优先级。
5. **复测**：上述修复后按同一金标准 v2 重跑全部类别。
