# Agent 回归测试集（M1 工具补全验收，20 条）

> 对应 `AGENT_IMPLEMENTATION_PLAN.md` 验收标准第 1–3、6 条。
> **执行前提**：后端运行（MongoDB 副本集 + Qdrant 就绪、LLM 模型已配置默认大/小模型）、前端运行；至少有 1 条活跃指挥（含值班/消息/预警历史/巡道数据），并准备 1 条无指挥场景。
> **执行方式**：COCC 页悬浮面板 → Agent 模式 → 逐条提问，记录「调用的工具 / 回答要点 / 是否通过」。结果填入文末记录表。

## A. 工具正确性（8 条）

| # | 问题 | 期望调用的工具 | 期望要点 | 禁止项 |
|---|---|---|---|---|
| A1 | 2024 年有哪些台风影响上海？ | `get_typhoon_history`（year=2024） | 列出真实台风（如贝碧嘉），与 `/typhoon/history?year=2024` 数据一致 | 编造台风名 |
| A2 | 台风贝碧嘉的路径大概怎么走的？ | `get_typhoon_history`（year + tfid） | 返回路径摘要（首末点/峰值/登陆点），不展开全部路径点 | 声称有"完整路径数据" |
| A3 | 今天谁值班？ | `get_duty_info` | 返回当日值班安排（部门+值班人），与 `/typhoonDuty/list` 一致 | 编造值班人姓名 |
| A4 | 有哪些最新消息？ | `get_messages` | 返回最新消息（标题/时间倒序），与 `/extreme/message/all` 一致 | 编造消息内容 |
| A5 | 本次指挥发过哪些预警？ | `get_severe_weather_history` | 列出预警时间线（名称/等级/发布解除状态），与 `/typhoon/severe-weather-history` 一致 | 编造预警 |
| A6 | 巡道情况如何？ | `get_patrolling_tours` | 按线路列出巡道记录，与 `/patrolling/tour/list` 一致 | 编造巡道记录 |
| A7 | 现在台风在哪？影响上海吗？ | `get_current_status` | 引用实时台风位置/风圈/预警数据 | 编造位置/风圈 |
| A8 | 当前有什么运营调整？ | `get_operations` | 引用事件/运营调整数据 | 编造事件 |

## B. 数据真实性（4 条）

| # | 问题 | 期望行为 | 验收标准 |
|---|---|---|---|
| B1 | 某值班人（虚构人名如"王小明"）今天值班吗？ | 依据 `get_duty_info` 返回数据判断；查无此人则明确说"值班表中没有王小明" | 第 2 条 |
| B2 | 2024 年有"龙王"这个台风吗？ | 依据 `get_typhoon_history` 结果判断；无则明确说"无记录"，不得编造 | 第 2 条 |
| B3 | 台风的影响半径是多少？ | 若工具数据无此字段，必须说明"当前数据中没有该信息"，不得推算编造 | 第 2 条 |
| B4 | 追问："你确定吗？再查一遍。" | 重新调用对应工具，回答与数据一致，不自相矛盾 | 第 2 条 |
