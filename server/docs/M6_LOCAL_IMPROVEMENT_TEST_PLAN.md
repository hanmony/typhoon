1. 不把任何 API Key、私钥、身份证、值班表、联系方式或内部通讯录提交 Git、截图或聊天。

## 4. 分阶段执行计划

### 阶段 A：冻结当前状态并做备份

**DeepSeek Harness 执行：**

- 记录当前 Git 提交、Node/npm、Docker、nginx、MongoDB、Qdrant 版本。
- 记录数据库数量：`kbdocuments=72`、`kbchunks=3002`、Qdrant `knowledge_base=3002`。
- 备份 MongoDB、Qdrant storage、`server/upload`、`server/assets`、`server/.env`；备份包不得进入 Git。
- 记录当前运行端口和启动命令，明确 3000 后端是否来自发布目录。

**你需要确认：**备份位置、备份日期，以及是否允许在备份完成后进行停机操作。

**Codex 审查：**检查备份清单、敏感文件排除规则和恢复演练结果。

### 阶段 B：建立真正可重复的本机发布

**DeepSeek Harness 执行：**

1. `npm run build` 前先停止正在使用 `dist` 的后端；禁止在运行中的 dist 上覆盖构建。
2. 按 `DEPLOY.md` 生成后端发布包：`dist`、`package.json`、`package-lock.json`、`assets`、`config`；不包含 `src`、`node_modules`、`.env`、`upload`、`logs` 和密钥。
3. 将后端放入 `C:\data\sch-typhoon\server`，执行 `npm install --omit=dev`，再用 `node dist/main` 或受控进程管理器启动。
4. 将 nginx 配置保存为仓库中的无密钥模板，例如 `deploy/nginx.conf.example`；实际路径和域名在部署机单独填写。
5. 固定启动、停止、重启和日志查看方式；不要依赖 `_launcher8.js` 这类未跟踪临时文件。
6. 完成“停止 → 构建 → 备份 → 切换 → 启动 → 冒烟测试”的一次完整演练。

**通过标准：**停止工作区进程后，`C:\data\sch-typhoon\server` 仍能独立启动；重启电脑后可按文档恢复；源码目录不再是运行依赖。

### 阶段 C：固定基础依赖和配置

**DeepSeek Harness 执行：**

- 将 Qdrant 镜像或 Windows 程序固定到与 `@qdrant/js-client-rest` 兼容的版本，不能使用 `latest`。
- 明确 MongoDB 副本集、Qdrant 持久化目录和端口；重启容器后数据仍存在。
- 使用配置清单核对 `DATABASE_URI`、`LLM_*`、`EMBEDDING_*`、`QDRANT_*`、`TYPHOON_API_*` 和 `QWEATHER_*`。
- 明确 `EMBEDDING_DIMENSION=1024` 与现有 Qdrant 向量一致；不能更换 embedding 模型后直接复用旧向量。
- 确认 `llmmodels`（无下划线）中的默认模型，避免误把模型写入未被服务读取的 `llm_models`。

**你需要确认：**学校环境允许使用哪个 Qdrant 版本、哪个 LLM/Embedding 服务，以及是否允许访问外网 API。

### 阶段 C2：先修复管理员密码和公网访问安全

这是新增的 P0 阶段，必须在使用学校公网入口登录前完成。

**DeepSeek Harness 执行：**

1. 修改 `server/src/main.ts`：只在数据库不存在 `admin` 时创建初始管理员；已有 `admin` 时绝不在启动过程中覆盖密码。
2. 初始管理员密码不再硬编码为固定默认值。部署时从一次性环境变量或人工初始化流程设置，初始化后立即删除一次性值。
3. 增加自动测试：已有管理员启动后密码 hash 不变；首次空库能按受控方式创建管理员；缺少初始化凭据时安全失败或要求人工初始化。
4. 检查登录失败计数和锁定行为，测试时不要反复猜密码导致管理员锁定。
5. 为学校公网入口配置 HTTPS；在 HTTPS 生效前只允许通过学校 VPN/受信网络登录。
6. 检查防火墙：公网只开放 nginx 的 HTTPS 入口；3000、27017、6333/6334 不直接暴露公网。

**你需要执行：**修复部署后，用 Edge 在学校 VPN 或本机受信网络内修改管理员密码。输入普通新密码，不输入 SM3 字符串；修改后退出、重新登录、重启服务再登录，三次均成功才算通过。

**通过标准：**重启后新密码仍有效、旧默认凭据失效、数据库中只保存 bcrypt 结果、登录请求通过 HTTPS 或受信 VPN 传输。

### 阶段 E：真实模型质量测试

**你提供问题，DeepSeek Harness 执行并保存脱敏结果：**

### 阶段 F：真实性能测试和优化决策

**DeepSeek Harness 执行：**用真实模型连续运行至少 10 次，分别记录普通问答首 token、研判总时长、工具轮数、超时和错误。

**当前问题：**已观察到首 token 3.442 秒，研判一次 53.493 秒、另一次 15.668 秒，波动较大。必须先决定以下方案之一：

- 换用更快模型；
- 关闭或降低 reasoning；
- 限制研判报告长度；
- 将“<3 秒/<30 秒”改为部署环境分位数指标，并由业务负责人批准。

**通过标准：**方案确定前不能宣称性能验收完成；方案确定后，至少报告 P50/P95、样本数、模型名和网络环境。
