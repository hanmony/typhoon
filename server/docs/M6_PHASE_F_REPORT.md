## 二、方法与口径（修订后）

1. **统计口径**：P50/P95/成功率只统计 **30 次正式样本**；2 次预热（含冷启动首测）单独展示、不计入任何统计。
2. **SSE 成功判定（强化）**：一次请求成功必须同时满足——
   - HTTP 状态 = 201；
   - `Content-Type` 含 `text/event-stream`；
   - 流尾部收到 `[DONE]`；
   - 无协议 error 事件（`event: error` 或 `{"type":"error"}`/顶层 `error` 字段）；
   - 无 malformed 事件（`data:` 行 JSON 解析失败）；
   - 期望内容出现（chat/agent 至少 1 个 token 事件；kb 需 sources + content；研判需 analysis 卡片 + token）。
   失败分类：`timeout / stream_error / http_<状态码> / ct_not_sse / proto_error / malformed / no_done / empty`，逐类计数。
3. **重复 token 检测范围（说明）**：主指标 `相邻重复对数` = 相邻且内容完全相同的 token/content 事件对数，用于检测 **SSE 协议层重复发送缺陷**；辅助指标 `重复事件总数` = 任意位置重复出现的相同事件数（信息性，可能包含正常重复字）。本报告两者均报告；文本级 LLM 重复用词不属于协议缺陷，不在判定范围。
4. **并发短测**：档位 **1/2/3/5**（补测并发 2）；每档 5 轮；并发段前**等待 65s 排空平台节流窗口**，使各档成功率只反映该档本身（否则会叠加前序类别的限流余量，口径不纯）。
5. **验证脚本串行执行**：平台节流器（15 次/60s/IP）下并发运行验证脚本会互相挤占配额（实测 release-verify 与 m5-eval 并发跑时 chat 项 429）；故最终回归均串行执行、间隔排空。

### 基线发现的问题（均已定位）

1. **kb 检索慢（主因）**：kb 每次提问都调远程 embedding（Qwen3-Embedding-8B，1024 维），实测单次 **7~10s**，占 kb 总时延一半以上；chat 的 RAG 路径与 agent 的 kb 工具同样受影响。
2. **思考参数不可关**：A/B 探测 5 种参数写法（`thinking:{type:disabled/enabled}`、`reasoning_effort:low`、`enable_thinking:false`、baseline）——网关对关闭思考基本忽略（各变体 thinking 事件 2~7 个）。**结论：不追求关闭思考，靠 prompt 长度与缓存控制时延。**
3. **平台节流器**（原始代码，非本项目新增）：chat/agent/研判接口 `@Throttle 15 次/60 秒/IP`，nginx 反代后所有用户共享 127.0.0.1 配额。并发 3 → 成功率 33.3%，并发 5 → 0%（全部 `429 ThrottlerException`）。**决策（用户已批准）：不改平台，业务并发按 1–2 人验收；429 现象移交平台部门。**

## 四、性能优化与验证

### 优化：Embedding 查询向量 LRU 缓存（`embedding.service.ts`）

- 指挥室高频重复提问场景，同一问题只算一次 embedding，命中后跳过 7~10s 远程调用；
- 缓存键 = 规范化问题文本，命中返回**同一向量** → Qdrant 检索语义与未缓存时一致；
- **LRU 语义修正（Codex 审查项 6）**：命中即刷新最近使用位置（删除后重插）；容量 `EMBEDDING_CACHE_SIZE` 为非正数/非法值时按 **0** 处理（禁用缓存，行为与未加缓存完全一致）；
- 默认容量 256（约 1MB 内存）；仅缓存 `embedQuery`（单问题），批量建索引 `embedTexts` 不缓存。

### 验证 1：单元测试（`embedding.service.spec.ts`，**7/7 通过**）

| 用例 | 结果 |
|---|---|
| 同一问题第二次命中缓存，API 只调用一次，返回同一向量 | ✅ |
| 不同问题不共享缓存 | ✅ |
| LRU：命中后刷新最近使用位置，容量满淘汰最久未用 | ✅ |
| 容量 0：禁用缓存 | ✅ |
| 容量负数：按 0 处理 | ✅ |
| 容量非法值（"abc"）：按 0 处理 | ✅ |
| 批量 embedTexts 不经过缓存 | ✅ |

### 验证 2：缓存 A/B（`kb-cache-ab.js`，**8/8 通过**）

双实例对比：A=缓存开（3000）、B=缓存关（`EMBEDDING_CACHE_SIZE=0`，3001），同一问题各 3 次：

| 对比 | 结果 |
|---|---|
| A 内部：冷启动 vs 缓存命中（score **精确相等**=同一向量） | ✅ |
| B 内部：缓存关每次重算（结构/顺序/内容一致，score 容差 0.001——独立 embedding 调用存在 ~1e-4 非确定性） | ✅ |
| 跨实例：缓存开 vs 关（sources 数量/顺序/documentName/chunkIndex/content 一致） | ✅ |
| 回答非空且 HTTP 200/201 | ✅ |

结论：缓存不改变检索输入，**sources 结构与排序完全一致**；score 差异仅为独立 embedding 调用的模型非确定性（~1e-4），非缓存引入。
