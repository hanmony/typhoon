# M6 阶段 F 报告：真模型性能优化与稳定性测试（2026-08-20）

> 对应 `M6_LOCAL_IMPROVEMENT_TEST_PLAN.md` 阶段 F。目标：真 LLM 下智能体性能稳定、准确率/精确率/召回率有保证。
> 方法：真实模型每类连续 30 次 + 1/3/5 并发短测；区分冷启动与预热；报告 P50/P95、SSE 中断率、重复 token、协议 error、超时率、请求失败率。
> 红线遵守：全部为**真实模型实测数据**（无 mock 结果）；未打印/提交任何密钥；未降低检索与防编造标准（缓存优化检索语义不变）。

### 基线发现的问题（均已定位）

1. **kb 检索慢（主因）**：kb 每次提问都调远程 embedding（Qwen3-Embedding-8B，1024 维），实测单次 **7~10s**，占 kb 总时延一半以上；chat 的 RAG 路径与 agent 的 kb 工具同样受影响。
2. **思考参数不可关**：A/B 探测 5 种参数写法（`thinking:{type:disabled/enabled}`、`reasoning_effort:low`、`enable_thinking:false`、baseline）——网关对关闭思考基本忽略（各变体 thinking 事件 2~7 个），纯模型首 token 稳定 ~2.2s（短 prompt）。**结论：不追求关闭思考，靠 prompt 长度与缓存控制时延。**
3. **平台节流器**（原始代码，非本项目新增）：chat/agent/研判接口 `@Throttle 15 次/60 秒/IP`，nginx 反代后所有用户共享 127.0.0.1 配额。并发 3 → 成功率 86.7~93.3%，并发 5 → 0%（全部 `429 ThrottlerException`）。**决策（用户已批准）：不改平台，业务并发按 1–2 人验收；429 现象作为平台发现移交平台部门。**

## 三、性能优化（已实施并部署）

### 优化①：Embedding 查询向量 LRU 缓存（`embedding.service.ts`，commit 3d48a9c）

- 指挥室高频重复提问场景，同一问题只算一次 embedding，命中后跳过 7~10s 远程调用；
- 缓存键 = 规范化问题文本，命中返回**同一向量** → Qdrant 检索语义与未缓存时完全一致，**不影响精度/召回**；
- 默认容量 256（约 1MB 内存），可用 `EMBEDDING_CACHE_SIZE` 配置；仅缓存 `embedQuery`（单问题），批量建索引 `embedTexts` 不缓存；
- 部署后验证：**release-verify 7/7 PASS、m5-eval 9/9 PASS（含研判一致性 21/21 严格相等）**——检索质量零变化。
